# HDF5 File Attributes Format Documentation

## Overview
This document describes all attributes stored in HDF5 files generated by `generate_above_augmented_demos.py` and combined by `combine_hdf5_files.py`.

## File Structure
```
data/
  demo_0/
    actions          (dataset)
    dones            (dataset)
    rewards          (dataset)
    robot_states     (dataset)
    states           (dataset)
    obs/             (group)
      joint_states
      gripper_states
      ee_pos
      ee_ori
      ee_states
      agentview_rgb
      eye_in_hand_rgb
    metadata/        (group)
      (attributes)
      (datasets)
```

## Top-Level Datasets

### 1. `actions`
- **Shape**: `(T, 7)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: OSC (Operational Space Control) delta commands for end-effector control
- **Contents**: `[delta_pos(3), delta_ori(3), gripper(1)]`
  - First 3 elements: End-effector position delta (meters)
  - Next 3 elements: End-effector orientation delta (axis-angle, radians)
  - Last element: Gripper command (negative = open, positive = close)
- **Units**: Position delta in meters, orientation delta in radians (axis-angle), gripper command (dimensionless)
- **Note**: These are **delta commands** (relative to current pose), not absolute joint positions

### 2. `dones`
- **Shape**: `(T,)`
- **Dtype**: `uint8`
- **Format**: Array
- **Description**: Episode termination flags (1 = episode ended, 0 = continuing)
- **Values**: 0 or 1

### 3. `rewards`
- **Shape**: `(T,)`
- **Dtype**: `uint8`
- **Format**: Array
- **Description**: Reward signals at each timestep
- **Values**: 0 or 1 (binary reward)

### 4. `robot_states`
- **Shape**: `(T, 9)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: First 9 elements of proprioceptive state
- **Contents**: Joint positions, velocities, and other proprioceptive information

### 5. `states`
- **Shape**: `(T, N)` where N varies by environment (typically 25-84)
- **Dtype**: `float64`
- **Format**: Array
- **Description**: Full MuJoCo simulation state (qpos + qvel)
- **Contents**: 
  - `qpos`: Generalized positions (includes positions and quaternions for free joints)
  - `qvel`: Generalized velocities
- **Orientation Format**: Quaternions in `qpos` (MuJoCo convention: [w, x, y, z] for free joints)
- **Note**: This is the raw MuJoCo state, not processed orientation data

## Observations (`obs/`)

### 6. `joint_states`
- **Shape**: `(T, 7)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: 7-DOF joint positions
- **Units**: Radians

### 7. `gripper_states`
- **Shape**: `(T, 2)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: 2-element gripper positions
- **Units**: Gripper opening width (m)

### 8. `ee_pos`
- **Shape**: `(T, 3)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: 3D end-effector position
- **Contents**: `[x, y, z]` in world coordinates
- **Units**: Meters

### 9. `ee_ori`
- **Shape**: `(T, 3)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: End-effector orientation
- **Orientation Format**: **AXIS-ANGLE** (3D vector)
- **Contents**: `[ax, ay, az]` - axis-angle representation (exponential coordinates)
- **Conversion**: Converted from quaternion using `quat2axisangle()` function
- **Units**: Radians (magnitude of vector = rotation angle, direction = rotation axis)
- **Note**: This is **NOT** Euler angles, but axis-angle representation

### 10. `ee_states`
- **Shape**: `(T, 6)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: Combined end-effector pose
- **Contents**: `[ee_pos(3), ee_ori(3)] = [x, y, z, ax, ay, az]`
- **Orientation Format**: **AXIS-ANGLE** (3D vector)
- **Units**: Position in meters, orientation in radians (axis-angle)

### 11. `agentview_rgb`
- **Shape**: `(T, 256, 256, 3)`
- **Dtype**: `uint8`
- **Format**: Array
- **Description**: Agent viewpoint RGB images
- **Contents**: RGB images from agent's camera
- **Values**: 0-255

### 12. `eye_in_hand_rgb`
- **Shape**: `(T, 256, 256, 3)`
- **Dtype**: `uint8`
- **Format**: Array
- **Description**: Wrist camera RGB images
- **Contents**: RGB images from wrist-mounted camera
- **Values**: 0-255

## Metadata (`metadata/`)

### Attributes (stored as HDF5 attributes):

#### 13. `iteration`
- **Type**: `int64`
- **Description**: Augmentation iteration number
- **Values**: 
  - `0`: Non-shifted demo (original above pose)
  - `>0`: Shifted demo (randomly shifted above pose)

#### 14. `shifted`
- **Type**: `bool`
- **Description**: Whether this demo was shifted from the original above pose
- **Values**: `True` or `False`

#### 15. `target_timestep`
- **Type**: `int64`
- **Description**: Target timestep from original demo (when object was reached)

#### 16. `trigger_timestep`
- **Type**: `int64`
- **Description**: Timestep when above region was reached in augmented demo

#### 17. `shift_info` (optional)
- **Type**: `dict` (stored as JSON string)
- **Description**: Shift parameters (only present if `shifted=True`)
- **Contents**: 
  ```json
  {
    "xy_shift": [x_shift, y_shift],  // Position shift in XY plane (meters)
    "z_shift": z_shift,               // Position shift in Z direction (meters)
    "ori_shift": ori_shift_deg        // Orientation shift around z-axis (degrees)
  }
  ```

### Datasets (stored as HDF5 datasets):

#### 18. `above_pose`
- **Shape**: `(7,)`
- **Dtype**: `float64`
- **Format**: Array
- **Description**: Above pose used to start the augmented demonstration
- **Contents**: `[x, y, z, w, x, y, z]` = `[pos(3), quat(4)]`
  - Position: `[x, y, z]` in world coordinates (meters)
  - Quaternion: `[w, x, y, z]` in MuJoCo convention (NOT axis-angle!)
- **Orientation Format**: **QUATERNION** (4D vector) in `[w, x, y, z]` format
- **Note**: This is different from `ee_ori` and `ee_states` which use axis-angle format
- **Units**: Position in meters, quaternion (unit quaternion)

## Key Points

### Orientation Formats:
1. **`ee_ori` and `ee_states`**: Use **AXIS-ANGLE** format (3D vector)
   - Converted from quaternion using `quat2axisangle()`
   - Format: `[ax, ay, az]` where magnitude = angle, direction = axis
   - Units: Radians

2. **`above_pose` (metadata)**: Uses **QUATERNION** format (4D vector)
   - Format: `[w, x, y, z]` (MuJoCo convention)
   - This is the raw quaternion, not converted to axis-angle

3. **`states` (top-level)**: Contains full MuJoCo state
   - Includes quaternions in `qpos` for free joints
   - Format: `[w, x, y, z]` (MuJoCo convention)

### Consistency:
- **All observations (`obs/`) use axis-angle format** for orientation
- **Metadata uses quaternion format** for `above_pose`
- **MuJoCo state (`states`) uses quaternion format** in qpos

### Data Preservation:
- `combine_hdf5_files.py` preserves all data formats exactly (direct copy)
- No conversion is performed during combination
- All formats remain as originally saved

## Verification
To verify the format of any HDF5 file, run:
```bash
python3 scripts/phase3/pipeline/utils/list_hdf5_attributes.py
```

This will analyze the first demo in the first HDF5 file and display all attributes with their formats and shapes.
